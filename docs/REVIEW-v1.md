# Аудит расширения Backloggd i18n 1.0.0 (архив)

> Это исторический документ: он описывает проблемы версии 1.0.0, которые были исправлены в 2.0.0. Ссылки на `audit/check.js` и `locales/en.js` относятся к старой структуре проекта.

Дата: 2026-11-03. Проверены все файлы проекта: `manifest.json`, `content.js`, `content.css`, `locales/ru.js`, `locales/en.js`, `popup/*`, `icons/*`, `README.md`.
На момент аудита живой сайт из среды был недоступен; в версии 2.0.0 разметка Backloggd уже проверена и описана в `docs/DOM-RESEARCH.md`. Остальное ниже воспроизведено запуском `node audit/check.js` (файл удалён в 2.0.0).

## Краткий вердикт

Упаковка (манифест, попап, иконки, переключатель) сделана аккуратно, но **ядро перевода построено на неверной модели**: оно заменяет отдельные слова и обрывки фраз в любом текстовом узле страницы. Из-за этого ломаются названия игр и пользовательский контент, появляется смешанный «англо-русский» текст, а полный обход DOM на каждую мутацию даёт секундные подвисания. Русский словарь в основе приличный, но содержит смысловые ошибки, рассогласованную терминологию и «грязные» ключи.

| Критерий | Оценка |
|---|---|
| Архитектура перевода | 3/10 |
| Корректность (не портит страницу) | 4/10 |
| Производительность | 3/10 |
| Точность и естественность RU-перевода | 6/10 |
| Терминология и единообразие | 5/10 |
| UX / оформление | 7/10 |
| Соответствие README | 3/10 |
| **Итого** | **~4,5/10 — рабочий прототип, не релиз** |

## 1. Критические дефекты реализации

### P0-1. Подстрочная замена слов портит названия игр и пользовательский текст

После точного совпадения `translateText()` перебирает **все 289 ключей** и заменяет их вхождения в любом месте строки (`content.js:241–257`). Среди ключей — **123 однословных**, включая `All`, `Port`, `Music`, `Series`, `Update`, `Season`, `Indie`, `Platform`, `Review`, `Games`. Защита `shouldSkipElement()` (`content.js:48–81`) закрывает лишь несколько классов, поэтому замена применяется к карточкам игр, названиям списков, заголовкам рецензий, комментариям и био.

Фактические результаты (из `audit/check.js`):

| Исходный текст | Получается | Ожидаемо |
|---|---|---|
| `PlayStation All-Stars Battle Royale` | `PlayStation Все-Stars Battle Royale` | без изменений |
| `Port Royale 4` | `Порт Royale 4` | без изменений |
| `My Top 10 Games of All Time` | `My Top 10 Игры of Все Time` | без изменений |
| `Music to play to` | `Музыкальные to play to` | без изменений |
| `Everything or Nothing` | `Everything или Nothing` | без изменений |
| `Season 2 Battle Pass` | `Сезон 2 Battle Pass` | без изменений |
| `Series X` | `Серия X` | без изменений |
| `Indie World` | `Инди World` | без изменений |
| `Update 1.5 is live` | `Обновление 1.5 is live` | без изменений |

Это прямо противоречит обещанию README («названия игр … не ломаются автопереводом»). Обратимое переключение в EN спасает (оригинал хранится в `_originalEnText`), но в RU-режиме страница выглядит сломанной.

**Причина:** попытка переводить UI через пословную замену. Для названий игр и UGC это не работает в принципе.

### P0-2. Служебные слова переведены как самостоятельные ключи

В словаре есть ключи-обрывки предложений: `"on": "на платформе"`, `"by": "от"`, `"or": "или"`, `"reviewed": "написал отзыв о"`, `"review": ...`. В отрыве от контекста они дают бессмыслицу:

| Исходный текст | Получается |
|---|---|
| `Based on your ratings` | `Based на платформе your Оценки` |
| `Ranked by difficulty` | `Ranked от difficulty` |
| `Games on my backlog` | `Игры на платформе my В планах` |
| `Log in to continue` | `Войти to continue` |
| `Rated 5 stars on Backloggd` | `Rated 5 stars на платформе Backloggd` |

`"on" → "на платформе"` явно появился из-за строки вида «reviewed <game> on <platform>», но перевод фрагмента без контекста невозможен: в 90 % случаев `on` — предлог, а не «на платформе».

### P0-3. Производительность: полный обход DOM на каждую мутацию

На каждый батч мутаций (debounce 40 мс) вызывается `applyLocalization()` → `translateNode(document.body)` (`content.js:368–373`). Для **каждого текстового узла**:

- `Object.keys(dict).filter(...).sort(...)` — сортировка 289 ключей (`content.js:237–240`);
- до 289 `new RegExp(...)` — по одному на каждый ключ (`content.js:244, 251`);
- для каждого элемента — до 10 вызовов `closest()` в `shouldSkipElement()`.

Замер на этой машине: **0,12–0,20 мс на один текстовый узел** (без совпадений). Для типовой страницы Backloggd это:

- 5 000 узлов → **0,6–1,0 с** на проход;
- 20 000 узлов → **2,4–4,0 с**.

Проход повторяется после каждой пачки мутаций — а лента Backloggd постоянно дозагружает карточки при скролле. Итог: рывки и «залипания» интерфейса, особенно на слабых машинах. Хуже того, обход выполняется **даже когда перевод выключен или выбран EN**: `getActiveDict()` вернёт `null`, но `translateNode` всё равно обойдёт весь DOM.

### P0-4. Возможный бесконечный цикл MutationObserver на `<option>`

В ветке `OPTION` (`content.js:322–331`) используется `node.textContent = ...`. Присваивание `textContent` **всегда** удаляет и создаёт дочерний текстовый узел, то есть генерирует `childList`-мутацию, которую наблюдатель и слушает. Получается цикл: запись → мутация → `applyLocalization` через 40 мс → запись → … Если на странице есть нативный `<select>` (например, фильтр), вкладка будет постоянно пересобирать DOM и грузить CPU.

Отдельно: наблюдатель не слушает `characterData` (`content.js:421–426`), поэтому обновления текста «на месте» (счётчики времени, смена статуса) он не видит.

### P0-5. Устаревший кэш оригинала перетирает обновлённый текст сайта

`_originalEnText` записывается один раз и больше не обновляется (`content.js:275–277`). Если сайт позже меняет текст в том же узле (таймер `0h → 1h`, `Follow → Following`, счётчик), при следующем полном проходе расширение снова переведёт **старый** оригинал и вернёт его на место. Пример: узел «0h» переведён в «0 ч»; сайт пишет «1h»; следующий проход берёт `_originalEnText = "0h"` и снова ставит «0 ч» — актуальное значение потеряно.

Нужно сравнивать текущее значение с последним записанным и обновлять оригинал, если сайт его изменил.

### P0-6. Turbo: наблюдатель умирает после первого перехода

`observer.observe(document.body, ...)` вызывается один раз (`content.js:448, 453`). Turbo Drive при навигации **заменяет элемент `<body>`**, поэтому наблюдатель остаётся на отсоединённом узле: после первого перехода динамические блоки (бесконечная лента, модалки, вкладки) больше не переводятся до перезагрузки. Обработчики `turbo:load` заново применяют перевод, но не переподписывают наблюдатель.

Дополнительно: Turbo кэширует снимок DOM **вместе с уже переведённым текстом**. При возврате «назад» в снимке русский текст без меток `_originalEnText`, и переключение на EN уже не восстановит английский.

### P0-7. Первое совпавшее regex-правило обрывает обработку

Цикл по `REGEX_RULES` делает `return` после первого совпадения (`content.js:225–230`). Поэтому `Released in 2024` превращается в `Released в 2024 г.` (сработало правило «in YYYY»), а `Released` → «Вышедшие» уже не применяется. Любая строка, где сработало правило, остаётся частично английской.

### P0-8. Обращение к словарю без проверки собственных свойств

`if (dict[trimmed])` (`content.js:212`) читает и унаследованные свойства прототипа. Проверено: текстовый узел `toString` превращается в `[object Undefined]`. Нужен `Object.hasOwn(dict, key)` или `Map`.

## 2. Дефекты уровня P1

1. **Дыры в защите контента.** Проверка `.review-body` / `#collapseSummary` выполняется только для неинтерактивных элементов (`content.js:64–70`): любой `<a>` внутри текста рецензии уже переводится. Не защищены комментарии, записи журнала, описания списков, био, заголовки рецензий, `[contenteditable]`. Селекторы вида `.game-text-centered`, `.review-game-name` выглядят догадками и не проверены на живом DOM; структурного правила `a[href^="/games/"]` нет.
2. **EN/выключенный режим всё равно обходит DOM** (см. P0-3) — впустую.
3. **Нет синхронизации между вкладками:** слушателя `chrome.storage.onChanged` нет, переключение в одной вкладке не обновляет другие.
4. **Popup молча теряет сообщение.** `chrome.tabs.sendMessage` вызывается без callback (`popup/popup.js:40–49`); если content script не внедрён (страница открыта до установки/перезагрузки расширения), пользователь видит «переключилось», а страница не меняется. Нужен callback + `chrome.runtime.lastError` + подсказка «обновите страницу».
5. **Атрибуты переводятся только по точному совпадению** — `placeholder`, `title`, `aria-label`; нет `alt`, `value`, `data-original-title` (Bootstrap-тултипы). Плейсхолдер «Search games» остаётся английским.
6. **Нет `document.documentElement.lang = 'ru'`** и перевода `document.title` — минус к доступности и к виду вкладки.
7. **Контекст расширения может инвалидироваться** после обновления/перезагрузки — `chrome.storage.sync.get` бросит исключение, перевод замрёт без сообщения.
8. **Переключатель в шапке** при выключенном переводе меняет язык «в пустоту» (бейдж `OFF`, эффекта нет); `updateLanguageSwitcherBadge()` пишет inline-стиль поверх CSS.
9. **Правило `^h$`** переводит любой отдельный текстовый узел «h» в «ч»; правило часов не понимает `16h 30m` и `1 hour`.
10. **Плюрализация и числа не обрабатываются:** `1 Likes → 1 Лайков`, `1.2K Likes → 1.2K Лайков` (латинская `K`, точка вместо запятой).

## 3. Качество русского перевода

### 3.1. Смысловые ошибки

| Ключ | Сейчас | Проблема | Предложение |
|---|---|---|---|
| `Obscurity` | `Редкость (неизвестность)` | это сортировка «по неизвестности», а не редкость; калька с пояснением в скобках | `По неизвестности` |
| `Powered by` | `При поддержке` | «powered by» = «работает на», а не «при поддержке» | `Работает на` |
| `Forgot your password? Resend` | `Забыли пароль? Восстановить` | «Resend» — отправить письмо повторно, а не восстановить | `Забыли пароль? Отправить ещё раз` |
| `…games you've played…` | `…которую прошли…` | «played» ≠ «прошли» (completed), смысл сузился | `…в которую играли…` |
| `Create and organize games with lists` | `Создавайте и сортируйте списки игр` | «organize» — упорядочивать, а не сортировать | `Создавайте списки игр и упорядочивайте их` |
| `Submit feedback` | `Оставить отзыв` | feedback ≠ review; конфликт с «отзывом» оставляет двусмысленность | `Оставить обратную связь` |
| `Last Played` | `По последней игре` | двусмысленно (какая «последняя игра»?); это сортировка по последнему запуску | `По последнему запуску` |
| `Top Liked` | `Самые популярные` | потеряно «по лайкам», дублирует `Popularity` | `По лайкам` |
| `Search` | `Поиск...` | многоточие из плейсхолдера попало в пункт навигации; в «Search games» даёт «Поиск... Игры» | разделить ключи: `Search` → `Поиск`, `Search games` → `Поиск игр` |
| `Card & Board Game` | `Настольные и карточные` | перепутан порядок и потеряно «Game» | `Карточные и настольные игры` |
| `Windows PC` | `Windows ПК` | калька, неестественный порядок | `ПК (Windows)` |
| `Terms of Service` / `Privacy Policy` | `Условиями обслуживания` / `Политикой конфиденциальности` | творительный падеж «пришит» к фразе согласия, но эти же строки стоят отдельно в футере — там падеж неверный; «обслуживание» — не юридический термин | `Условия использования` / `Политика конфиденциальности` + переписать фразу согласия целиком |
| `I agree to the … and agree to the …` | `Я согласен с … и согласен с …` | дублирование глагола | `Я принимаю Условия использования и Политику конфиденциальности` |
| `Sleeper hits` | `Недооценённые хиты` | sleeper hit — неожиданный хит, не обязательно недооценённый | `Неожиданные хиты` |

Плюс ошибки, видимые только в собранной фразе: `Я согласен с Условиями обслуживания и согласен с Политикой конфиденциальности`, `Наша политика cookie` (→ `Политика использования cookie`).

### 3.2. Рассогласованная терминология

Одна и та же сущность называется по-разному — это главная стилистическая проблема словаря.

| Понятие | Варианты в `ru.js` |
|---|---|
| Reviews / review | `Отзывы` (навигация), `Рецензии`, `рецензия`, `отзыв`, `обзоры` (в тексте про ленту) |
| Backlog | `В планах` (статус), `В бэклоге` (`Backlogs`), `В бэклог` (`Add to Backlog`), `бэклог` (в прозе) |
| Lists | `Списки`, `тематические подборки`, `подборки` |
| Journal | `Журнал`, `дневник`, `ежедневный дневник` |
| Wishlist | `Желаемое`, `В желаемом`, `список желаемого` |
| Feedback / review | и то и другое — `отзыв` |
| Extras / Expansion | оба — `Дополнения` (коллизия в блоке связей игры) |
| Bundle | `Комплект (Бандл)`, `бандлов` |

Отдельно — **разнобой грамматических форм статусов**: `Сыграно` (причастие), `Играю` (глагол 1-го лица), `В планах` (предлог), `Желаемое` (прилагательное), `Брошено` (причастие). В одном ряду чипов это выглядит небрежно. Лучше выдержать один стиль, например: `Сыграно / Играю → В процессе / Пройдено / Отложено / Брошено / В планах / В желаемом` (или везде глаголы: `Играл / Играю / Прошёл / Отложил / Бросил`).

`Completed` переведено как `Завершено`, хотя README обещает «Пройдено» — для геймерского интерфейса «Пройдено» естественнее и соответствует заявлению в документации.

### 3.3. Орфография, пунктуация, типографика

- Ё используется непоследовательно: `Закрепленные` (стр. 56), `путем` (стр. 76) — рядом с `ждёт`, `Недооценённые`.
- `1 Лайков`, `1 Оценок`, `1 Отзывов` — нет плюрализации; для русских счётчиков обязательны формы `лайк/лайка/лайков`.
- `1.2K Лайков` — латинская `K` и точка как десятичный разделитель; нужно `1,2 тыс. лайков`.
- `знаки подчеркивания` → `символы подчёркивания`.
- Многоточие `...` вместо `…`; в `Search` оно ещё и лишнее.
- `Ср. времени игры`, `Пак / Аддон`, `Редкость (неизвестность)`, `Комплект (Бандл)`, `Мордобой (Beat 'em up)` — смешение регистров и скобочных пояснений в коротких подписях.
- `Портативная электроника` для `Handheld Electronic LCD` — потерян LCD; `Старые мобильные` для `Legacy Mobile Device` — просторечно.

### 3.4. «Грязный» словарь

- **6 ключей с кириллицей внутри:** `Favorite Игры`, `Personal Оценки`, `Recently Оценено`, `Last Сыграно`, `User Оценка`, `Fade Сыграно`. Это следы генерации словаря по уже переведённой странице (round-trip). Ключи мёртвые (английский источник так не выглядит), но они засоряют словарь и могут сработать на пользовательском тексте.
- **17 ключей есть в `ru.js`, но отсутствуют в `en.js`** — в том числе 5 длинных абзацев и `Company/Developer/Publisher/Developers/Publishers`, `Show editions`. База и перевод рассинхронизированы.
- **`locales/en.js` вообще не используется кодом:** `content.js` читает только `BACKLOGGD_I18N_RU`, а EN-режим восстанавливает оригиналы из `_originalEnText`. Файл мёртвый, но создаёт иллюзию «базового словаря» и расходится с RU.
- Дубли по регистру и пробелам: `Expand`/`EXPAND`, `Sign up`/`Sign Up`, `In Bundles`/`In bundles`, `Sort by`/`Sort by ` — код и так ищет без учёта регистра, эти пары только шумят.

### 3.5. Пробелы покрытия

Словарь on ~289 ключей — мало для Backloggd. Проверенные примеры, которые остаются английскими или переводятся наполовину:

- `Backlogged` (статус) — отсутствует, поэтому `Backlogged in 2024` → `Backlogged в 2024 г.`;
- `Add to Wishlist` → `Add to Желаемое` (нет ключа);
- `Rate this game`, `Recently Played` → `Recently Сыграно`, `Show editions` (ключ есть только в RU);
- `Search games` (плейсхолдер) — не переводится;
- нет `hour/hours`, `minute/minutes`, `day/days`, `ago`, `Load more`, `Show more`, `Save`, `Cancel`, `Delete`, `Share`, `Report`, `Edit`, `Sort`, `Filter by`, `in progress`, `not played`;
- нет дат с временем, диапазонов, форматов `May 2025`, `2025–2026`.

Проверить фактическое покрытие на живом DOM нельзя без доступа к сайту — это отдельная задача (снять список строк со страниц и прогнать по словарю).

### 3.6. Что в переводе удачно

- Основная навигация и статусы в целом понятны: `Игры`, `Списки`, `Журнал`, `Профиль`, `Друзья`, `Подписки`, `Подписчики`, `Быстрая запись`.
- Геймерская лексика уместна: `На 100%`, `Бэклог`, `Инди`, `РПГ`, `Файтинг`, `Визуальная новелла`.
- Длинные абзацы главной страницы переведены адаптивно и читаются естественно, хотя местами теряют детали (см. ниже).
- Названия бренда `Backloggd` не транслитерируются — правильно.

В абзацах есть потери смысла: «to give you a quality score from a glance» и «so you don't miss a thing» выпали; «custom collection» стало «тематические подборки»; «by following each other to keep up-to-date» исчезло. Для маркетингового текста это допустимо, но это уже не «точный перевод», а пересказ — стоит решить, что заявлено.

## 6. План исправлений по приоритетам

### Шаг 1. Убрать пословную замену (P0-1, P0-2)

Переводить только **целые** текстовые узлы: точное совпадение (с нормализацией регистра/пробелов) и явные шаблоны для составных строк. Не заменять одиночные слова в произвольном тексте. Ключи `on`, `by`, `or`, `reviewed`, `All`, `Search` в пословном режиме удалить; вместо них — полные фразы или regex с контекстом.

```js
const has = (obj, k) => Object.prototype.hasOwnProperty.call(obj, k);

function translateNodeText(text, dict) {
  const t = text.trim();
  if (has(dict, t)) return text.replace(t, dict[t]);
  const lower = t.toLowerCase();
  for (const [k, v] of lowerMap) if (k === lower) return text.replace(t, v);
  // только явные шаблоны, без общих словарных слов
  for (const rule of COMPILED_RULES) {
    if (rule.re.test(t)) return text.replace(t, t.replace(rule.re, rule.replace));
  }
  return null;
}
```

### Шаг 2. Структурно защитить контент (P0-1, P1-1)

Один `closest()` по объединённому селектору вместо десяти, с кэшем в `WeakMap`:

```js
const PROTECTED = [
  'a[href^="/games/"]', '[data-game-id]', '.game-title', '.card-title',
  '.review-body', '.review-title', '.journal-entry', '.comment-body',
  '.list-description', '.bio', '[contenteditable]', '.navbar-brand'
].join(',');
```

Плюс: не переводить ничего внутри `PROTECTED`; убрать исключение для ссылок внутри рецензий.

### Шаг 3. Производительность (P0-3)

- Скомпилировать регулярки и отсортированные ключи **один раз** при инициализации.
- Обрабатывать только `mutation.addedNodes` и `characterData`, а не весь `body`.
- Помечать обработанные узлы `WeakSet`, чтобы не ходить по ним повторно.
- Немедленно выходить, если `dict == null` (EN/выключено).
- Кэшировать результат `shouldSkipElement` в `WeakMap`.

Ожидаемый эффект: проход по 5 000 узлов — единицы миллисекунд вместо ~1 с.

### Шаг 4. Наблюдатель и Turbo (P0-4, P0-6)

```js
const observer = new MutationObserver((records) => {
  if (!getActiveDict()) return;
  const added = [];
  for (const r of records) {
    if (r.type === 'characterData') added.push(r.target);
    else r.addedNodes.forEach((n) => added.push(n));
  }
  schedule(added);
});
observer.observe(document.documentElement, {
  childList: true, subtree: true, characterData: true
});
```

- Наблюдать `document.documentElement`, а не `body`.
- Перед `turbo:before-cache` восстанавливать оригиналы (или очищать кэш снимка), после `turbo:load` — переподписываться.
- Для `OPTION` писать в текстовый узел, а не в `textContent`, и только если значение реально изменилось.

## 7. Как воспроизвести

```powershell
node audit/check.js
```

Скрипт загружает `locales/en.js` и `locales/ru.js`, повторяет `translateText()` из `content.js` и печатает: расхождение ключей, «мёртвые» и кириллические ключи, примеры порчи строк, оценку стоимости прохода по DOM.

Ограничение: живой сайт недоступен, поэтому селекторы и наличие `<option>`/Turbo-замены `<body>` не проверены в реальном DOM. Это первые вещи, которые нужно проверить в DevTools на backloggd.com.
